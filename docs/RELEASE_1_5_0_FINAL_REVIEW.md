## 2. 本轮查出并修复的缺陷

文案精简动的是字符串，但复查顺带在保存/导入与指纹面板两条链上抓到 12 个真实缺陷。全部按「先证可达性再修」处理，每一条都有对应回归用例与隔离变异红证（第 3 节）。

### 2.1 配置保存与导入（6 条，均为竞态）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 拉取模型期间保存的 PAT 会被模型刷新结果覆盖掉 | 刷新完成时用**陈旧**的 profile 快照整体替换，覆盖期间的新写入 | 刷新收尾改为对最新 profile 做字段级 transform（`mutateProfile`），不再整体替换 |
| 2 | 同时保存 API Key 与访问令牌，后保存的会把先保存的凭据删掉 | 两个凭据事务并发，各自基于旧引用删除对方的密钥 | 凭据创建与替换同属一个事务（`credentialTransactionMutex`），串行化 |
| 3 | 导入配置会绕过排队中的配置写入，把旧写入留在自己后面提交 | 导入没进写队列，直接落盘 | 导入整段包进 `credentialTransaction → profileMutation → configurationWrite` 三把锁 |
| 4 | 导入会被在飞的凭据创建压回，导入结果不是最终态 | 同上，两个方向都能互相越过 | 同上：导入等待在飞凭据创建提交并发布后才替换与删密钥 |
| 5 | 被模板切换失效掉的余额结果，会被排在其后的保存又写回磁盘 | 失效只改了内存快照，队列里的旧保存带着旧快照落盘 | 失效在**写锁内**发布，排队中的旧保存采样到的是已失效状态 |
| 6 | 取消测试后立刻重开，两轮会重叠互相覆写状态 | 取消时把任务句柄置空，取消中的旧任务失去保护；`isActive` 对取消中的 Job 已为 false | 取消后保留句柄直到 cleanup 真正完成，忙碌判据改为 `job.isCompleted == false` |

### 2.2 指纹检测面板（6 条）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 7 | 检测进行中，「手动粘贴」还能预填、开跑，与在飞的一轮抢状态 | `prefill` 只看 `isRunning` 标志，标志发布前的窗口挡不住 | 统一按 `runInFlight()` 拒绝（进行中 / 准备中 / 取消 cleanup 中一律拒绝） |

## 2. 调度改动：一条只在逐题发送时生效的闸门

```kotlin
private val serialGate = Mutex()          // kotlinx Mutex 是公平 FIFO
private suspend fun <T> serialized(block: suspend () -> T): T =
    if (_uiState.value.useParallel) block() else serialGate.withLock { block() }
```

## 2. 检测包更新到底哪里坏了（结论先说）

**App 内的「检查更新」没有问题。** 它读清单、比大小与 SHA-256、下载、原子安装这四步都在正常工作——线上没有新包可发而已。

坏的是**每日自动重建的发布侧**：上游 2026-10-03（`d53d3f5b`）把它自带的核验器删掉了，模型从 53 个扩到 58 个，而 `tools/build_fingerprint_asset.py` 仍在按旧结构去取 `detector["verifier"]`，于是每次运行都在那一步抛 `KeyError: 'verifier'`，重建从未成功，`bank` 预发布里的包一直停在 53 个模型的旧版本。

修法（本轮已实施）：
- `tools/build_fingerprint_asset.py`：魔数升到 `LMFPA003`，不再写核验器段；子集/裁剪路径对没有 `verifier` 的 detector 也不再假设它有。
- `tools/publish_bank.py`：格式版本从**文件自身的魔数**推导（`LMFPA002`→2、`LMFPA003`→3），清单不再写死。
- App 侧：`FingerprintBank` 同时认 `LMFPA003` 与旧的 `LMFPA002`，旧包按长度整段跳过核验器（跳过顺序与旧写入端逐字段对齐）、不参与打分；打分只剩排序器 + `softmax(tau·排序)`；`BankUpdate` 的格式门是 `[2, 3]`。
- `SharedScoring` / `FingerprintViewModel` / `FingerprintScreen` 里核验器相关的字段与那句「排名与核验的第一候选不一致，请谨慎。」一并删除（进 `verify_apk_wording.py` 的退休表）。
- `tools/publish_bank.py` 的回读校验改为**可重试**：第一次重发（run 37156823597）里重建与发布都已成功，却在发布后的回读那一步被 `HTTP 503: Service Unavailable` 打断——刚传上去的资产还在 CDN 传播，读回拿到 503；重试与「字节不一致」走同一条重试路径（`URLError`/`HTTPError` 都算瞬时，6 次 × 5 秒），只有真的连续失败才判红。

## 3. 本轮真缺陷

1. **旧格式包的核验器跳过被写错**（新测试抓出来的真缺陷，不是走查发现的）：`skipVerifier` 把逻辑头的 mean/scale/weights 当成**三个**各自带长度前缀的向量去跳，而旧写入端只写**一个**前缀覆盖三个向量。结果 `LMFPA002` 包在解析末尾报「已截断」。用 Python 重放字节布局定位（`active=[0,1,2,3,4,5]`、`headSize=6`、bias 是最后 8 字节），改成读一次前缀跳三次，`FingerprintLegacyPackageTest` 随即全绿。这条正是「新增的 002 迁移黄金向量测试」的价值：没有它，格式 2 的兼容路径会一直带着这个错位发布。
2. **参考张量位宽守卫没有任何测试覆盖**（变异 R10 一开始被判「存活」，追下去发现是**缺测试**）：`BankReader.skipQuantizedReferences` 的 `bits != 8 && bits != 16` 分支，夹具的位宽合法（16），所以任何用例都碰不到它。补了一条直接测两个读入口（`quantizedReferences` 与 `skipQuantizedReferences`）在 `bits ∈ {0,3,32}` 时都拒绝的测试，R10 随后被抓住。
3. 上一轮我已把「换位」做成了「指纹插到复制左边、复制不动」——这是**上一轮的实现错误**，本轮按反馈改回真正的两格互换（真正的缺陷记在这里，不留白）。
