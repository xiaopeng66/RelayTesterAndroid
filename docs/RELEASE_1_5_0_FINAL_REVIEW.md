## 2. 本轮查出并修复的缺陷

文案精简动的是字符串，但复查顺带在保存/导入与指纹面板两条链上抓到 12 个真实缺陷。全部按「先证可达性再修」处理，每一条都有对应回归用例与隔离变异红证（第 3 节）。

### 2.1 配置保存与导入（6 条，均为竞态）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 拉取模型期间保存的 PAT 会被模型刷新结果覆盖掉 | 刷新完成时用**陈旧**的 profile 快照整体替换，覆盖期间的新写入 | 刷新收尾改为对最新 profile 做字段级 transform（`mutateProfile`），不再整体替换 |
| 2 | 同时保存 API Key 与访问令牌，后保存的会把先保存的凭据删掉 | 两个凭据事务并发，各自基于旧引用删除对方的密钥 | 凭据创建与替换同属一个事务（`credentialTransactionMutex`），串行化 |
| 3 | 导入配置会绕过排队中的配置写入，把旧写入留在自己后面提交 | 导入没进写队列，直接落盘 | 导入整段包进 `credentialTransaction → profileMutation → configurationWrite` 三把锁 |
| 4 | 导入会被在飞的凭据创建压回，导入结果不是最终态 | 同上，两个方向都能互相越过 | 同上：导入等待在飞凭据创建提交并发布后才替换与删密钥 |
| 5 | 被模板切换失效掉的余额结果，会被排在其后的保存又写回磁盘 | 失效只改了内存快照，队列里的旧保存带着旧快照落盘 | 失效在**写锁内**发布，排队中的旧保存采样到的是已失效状态 |
| 6 | 取消测试后立刻重开，两轮会重叠互相覆写状态 | 取消时把任务句柄置空，取消中的旧任务失去保护；`isActive` 对取消中的 Job 已为 false | 取消后保留句柄直到 cleanup 真正完成，忙碌判据改为 `job.isCompleted == false` |

### 2.2 指纹检测面板（6 条）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 7 | 检测进行中，「手动粘贴」还能预填、开跑，与在飞的一轮抢状态 | `prefill` 只看 `isRunning` 标志，标志发布前的窗口挡不住 | 统一按 `runInFlight()` 拒绝（进行中 / 准备中 / 取消 cleanup 中一律拒绝） |
| 8 | 取消后已收到的回答丢失，重试要从头发 | 取消即清空本轮缓存 | 每个模型每道题的结论即时写入 `roundAnswers`，取消后仍在 |
| 9 | 只有最后一个模型失败的题没有「重试本题」入口 | 可重试判据只看最后一个模型的 progress | 改由**本轮全部模型**的缓存派生（`retryableFrom`） |
| 10 | 静默入场检查重复进入面板会发两次清单请求 | 第二次进入没识别第一次仍在飞 | 静默检查在飞时直接复用，只保留一个在飞请求；手动接管才发第二次 |
| 11 | 取消后新任务与垂死任务重叠覆写（与 #6 同源） | 同 #6 | 同 #6 |
| 12 | 「查看支持的模型」按包内顺序平铺，53 个模型难扫读 | 无分组 | 改为**按家族分组的弹窗**，名单来自当前包头 |

### 2.3 界面（同轮交付）

- 复制按钮去圆形涟漪并统一提示：新增 `ui/components/QuietIconButton|ClipboardCopy|ExternalLink`；「已复制」提示与复制动作走同一个组件（本题卡、模型名、失败项）。
- lm-detector 项目地址改为可点链接，点开交给浏览器；没有可处理的应用时如实提示。
- 筛选框去掉占位提示（`筛选模型` 作为 label 保留）；模型清单改为**弹窗**（筛选框右侧列表按钮 + 已选角标），主界面不再平铺长清单。
- 「并行发送三题」整行合并为一个无障碍控件：点**标题文字**即切换，读屏不再把标签与开关念成两个无关元素（实测点文字切换成功、无选中虚影）。
- 进面板的静默更新检查独立 busy，**让位手动**：不挡检测、不挡手动检查与下载按钮；手动操作接管在飞的后台检查。
- 中断后「重试本题」只补发被中断那一题并续出结果，不重跑整轮。
- 批次结果行可展开该模型自己的候选榜，行与行独立收起。

其它实测事实：

- 以上阶段全部是**在最终发布的那一份产物上**复跑的（重建后重新安装、重新跑完全部阶段），不是早先同号构建的成绩。
- 10500 → 10501 **原地升级成功，应用数据保留**（供应商配置、已安装检测包 53 个模型 / 3.3 MB 原样在）。
- 走查中出现的失败项逐条定性，**没有一条是产品缺陷**，也没有为了变绿而改动产品代码或放宽断言：
  - **走查脚本判据错**（4 处，均在脚本内修正后复测通过）：
    1. 早脚本用 uiautomator 树找「已复制」提示——系统 Toast 不进无障碍树，必须判 `dumpsys window` 里的 Toast 窗口（`Toast.makeText` 是真系统 Toast）；
    2. 早脚本读面板摘要行时屏幕已滚到结果区，属视口裁切伪装成功能缺失，改为按当前视口读结果行、再滚回顶部读摘要；
    3. 运行按钮的文案带勾选数量（「依次检测 2 个模型」），脚本用整串匹配自然扫不到，改为按前缀扫节点；
    4. 同一脚本切页后立刻取节点，抢在了上屏重绘之前，改为等到面板标志节点出现再取。
  - **脚本前置缺失**（1 处）：运行按钮在没勾选模型时按设计禁用，脚本续跑时没有先勾选，改为先自备勾选再点。
  - **环境外因**（2 次）：模拟器直连 `github.com` 被重置（一次 `Connection reset`、一次 15 s 握手超时），手动检查如实报「网络请求失败：…」——这正是手动路径该做的（静默路径同样情况下不提示）；重跑即「检测包已是最新」。
- 未发现需要改代码的新缺陷。
