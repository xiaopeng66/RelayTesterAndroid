# 界面文案精简方案（已实施）

状态：2026-10-02 用户批准后实施。发布前的回归、变异与设备验收见 `docs/RELEASE_1_5_0_FINAL_REVIEW.md`。

对象：Relay Tester Android 全仓用户可见文案。
依据：对 `app/src/main/java` 下全部 Compose 界面与弹窗、ViewModel 提示语、核心层错误文案的穷举盘点（612 条独立用户可见字符串）。

本方案只做「删冗余、压长句」，不改功能、不改判定逻辑、不动动态数据（模型名、延迟、字节数等一律原样）。

---

## 1. 盘点结论

| 判定 | 占比（条数） | 说明 |
|---|---|---|
| KEEP | ≈ 44% | 短、必要（按钮、标签、状态词），不动 |
| COMPRESS | ≈ 40% | 有信息但太长（说明段、helper 文本），压到一行为主 |
| MERGE | ≈ 10% | 同一件事在多处重复（安全说明、校验句），合并到一处 |
| DELETE | ≈ 6% | 纯解释、界面上已自明的空态与引导句 |

按字数看，**COMPRESS 组承担约 70% 的可减体积**，集中在模型测试屏、余额屏、指纹屏三处的说明段与输入框 helper。

---

## 2. 处置规则

1. **DELETE**：删除后界面上没有任何信息缺口（空态自明、操作可自明、与相邻元素重复）——直接删。
2. **COMPRESS**：信息必须留，但一句话能说清——压到 ≤ 20 字，能进 helper 的不占正文行。
3. **MERGE**：同一事实出现在两处以上——只留一处（通常在首次出现处或全局一处），另一处删。
4. 下列内容**一律不动**：
   - `contentDescription`（无障碍播报，删了是缺陷不是精简）；
   - 校验失败、协议切换、安全拒绝类错误（HTTP/超时/重定向/加密参数等）——它们是排查依据，只允许去掉「请稍后重试」这类尾巴；
   - 动态拼接的数据与单位；
   - 危险操作确认框里的**后果**描述（删除不可撤销、覆盖配置会清空结果）——保留结论，只删解释。

## 5. 量化目标与验收

- 不追求字符串条数下降：目标是把 ≥ 25 字的说明类文案从当前约 120 条压到 ≤ 15 条，整体可读字数下降约 35–45%。
- 验收方式：
  1. 改前/改后各跑一次文案统计脚本（`grep` 全仓 `Text(`/`label =`/`supportingText =` 的字符串字面量，统计长度分布），结果写进提交说明；
  2. 门禁 `:app:testOptimizedUnitTest` 保持全绿（当前 203/203；**无任何测试断言被改文案**，已核对）；
  3. `assembleOptimized --rerun-tasks` 0 警告；
  4. 420dpi 模拟器逐屏走查，确认删句后没有「孤立标题 / 空卡片 / 失去上下文的按钮」——这是本类改动唯一的真风险。

## 6. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 删掉的是用户唯一能看到的解释 | 例如「检测包未安装」的补救路径 | 只删与同屏元素重复的解释；空态保留一句行动指引 |
| 压缩后产生歧义 | 「同源请求」这类术语对普通用户偏难 | 保留关键名词（同源/明文/密钥），删解释性从句 |
| 无障碍退化 | 误删 `contentDescription` | 规则第 4 条：一律不动（走查时用 TalkBack 抽查三条路径） |
| 与既有文档不一致 | `docs/UI_OPTIMIZATION_V7_SPEC.md` 等引用了原文案 | 改动后同步该文档里被引用的句子 |
