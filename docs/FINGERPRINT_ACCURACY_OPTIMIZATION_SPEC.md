## 0. 结论摘要

1. **"我们比上游差 2.4 个点"这个前提不成立。** 86.8% 来自"只用质心"这条退化路径——它是当年验证移植正确性的交叉校验，不是 App 的实际算法。App 实际跑的是 `0.5·z(LDA) + 0.5·z(质心)`，在可复现的口径下测出 n=3 时逐回答 **89.4%**，而上游自报的是 **89.19%**；差值 0.2 点，而该指标本身的噪声底是 **±4.8 点**。差距测不出来。
2. **真正该修的是三件事，按性价比排序**：① 判别头（LDA）重训与正则化——**0 字节**，权重只有 91 KB，可走已建好的指纹库更新通道；② 置信度校准与"库外模型"判定——**+0.4 MB**，修掉"任何模型都会被自信地叫成库内最近的那个"；③ 测量协议本身——**0 字节**，否则任何"更准了"都无法证明。
3. **明确不做**：恢复 kNN。它单独用只有 42/53（比只用质心的 46/53 还差），在上游权重下不带来任何可测量的变化，而代价是 3.34 MB（int8 也要 +0.54 MB）。
4. 残余错误的位置决定了优化方向：**所有默认口径下的错例都是"同族近邻"**（`glm-5.3-flashx→glm-5.3-flash`、`opus-4.8→4.7`、`gemini-3.8→3.7`、`muse-spark-1.3-contributor→1.3`）。需要的是更强的判别头和更多参考样本，不是再堆组件。
5. 诚实边界：上游的切分分组我们没有，所以两边的百分比严格说不可直接比较；泄漏协议的 98.1% 不能对外讲，无泄漏协议下的 **88.7%（逐模型）/78.6%（逐回答）** 才是当前真实水平。

## 1. 先把事实钉住：现在测出来是什么

### 1.1 评估协议（本次复现，两个协议对照）

- 语料：上游 `shared_detector.json`（32.3 MB 文本），1,948 条可用参考回答、53 个模型、47 个不同 challenge。
- 切分：按 `challenge_id` 首次出现序号 `% 4 == 0` 留出 → 12 个留出 challenge、491 条留出回答；拟合半区 1,457 条。**按 challenge 切而不是按回答切**，否则同一道题会同时进训练和测试。
- 有效回答门槛：`max(80, ceil(expected_count * 0.55))`，与 App/上游一致。
- **frozen 协议**＝直接用制品里的 `lda_weights / lda_bias / head_params`（这些是在全部 1,948 条上拟合的，所以留出回答会漏进投影＝**泄漏**）；质心与 kNN 参考在两个协议里都只用拟合半区重算。
- **refit 协议**＝LDA 投影及其输入 mean/scale 也只用拟合半区重拟合（**无泄漏**）。这是唯一可以对外引用的数字。
- 三种粒度：**逐模型**（53 个决策，每模型取来自不同 challenge 的前 3 条留出回答）、**逐回答**（491 个决策，每条回答单独判）、**分块 n=k**（把 491 条按 k 条一组平均后再判，等价于 App 里"同一模型问 k 条再合并"的真实用法）。

### 1.2 测量的读数

| 变体 | 逐模型 (53) | 逐回答 (491) | 分块 n=3 (160) |
|---|---|---|---|
| **App 实际公式**（冻结＝泄漏） | 52/53 98.1% | 478/491 97.4% | 159/160 99.4% |
| **App 实际公式**（无泄漏） | 47/53 88.7% | 386/491 78.6% | 143/160 89.4% |
| 上游完整公式 `0.5LDA+0.25kNN+0.25质心`（冻结） | 52/53 98.1% | 478/491 97.4% | 159/160 99.4% |
| 上游完整公式（无泄漏） | 48/53 90.6% | 372/491 75.8% | 144/160 90.0% |
| 只用质心（**86.8% 的来源**，冻结） | 46/53 86.8% | 380/491 77.4% | 142/160 88.8% |
| 只用 kNN（冻结） | 42/53 79.2% | 322/491 65.6% | 128/160 80.0% |
| 上游 verifier 重新打分后 argmax（冻结） | 53/53 100.0% | —（需正好 3 条有效回答） | — |

要点：

- **kNN 项在这份库上测不出贡献**：加上它（上游权重）与不加（App 现在的权重）在冻结协议下逐回答完全相同（478/491），逐模型都是 52/53。而它单独用只有 42/53，比只用质心还差。ablation 脚本里"去掉 kNN"得到 53/53，但那一步同时改动了 LDA 与质心的相对权重，不是干净的"加/不加 kNN"对照——所以结论只能是"不值得为它花 3.34 MB"，不能说"它有害"。
- **verifier 只多修对一个模型**（`glm-5.3-flashx`，52→53），且上游自己的 `prediction` 仍然是排序的 top-1（verifier 的 `scores` 只喂给 `verification_score`/`verification_top`）。也就是说：verifier 的价值不在排名，而在于它**顺带产出一个"这条回答到底像不像库内模型"的判据**——这正是 App 现在完全没有的东西。
- 交叉校验：本次复现同时重跑了上游两个脚本（`ablation.mjs`、`ablation_lda.py`）的既有数字，9 项全部与原记录一致（46/52/53/48/45/49…），所以上表不是新造的口径。

### 1.3 噪声底：为什么"差 2.4 点"不是一个可以谈的量

- 分块 n=3 只有 160 个样本，89.4% 对应 95% 置信区间 **±4.8 点**；上游那个 89.19%（652/731）是 **±2.3 点**。两者之差的区间约 **±5.3 点**——0.2 点乃至 2.4 点的差异都埋在噪声里。
- 逐模型只有 53 个决策，±4 个模型（≈±8 点）以内都属于噪声。**任何"提升了 2 个点"的逐模型说法都不可信。**
- 逐回答有 491 个决策（±2.7 点），是唯一够用来调参的粒度。
- 另外：无泄漏重拟合的 LDA 是病态的——429 维特征里 **87.9% 的特征值 ≈ 0**（`frac|eig|<1e-6 = 0.879`），投影只保留了 52 个方向。这种数值条件下，小改动带来的排序抖动本身就很大，所以下面每一条"预期收益"都必须带噪声带读。

## 2. 误差落在哪里（无泄漏协议下的错例）

App 公式无泄漏口径的 6 个错例：`claude-opus-4.8→4.7`、`gemini-3.8-flash→3.7-flash`、`muse-spark-1.3-contributor→1.3`、`glm-5.3-flashx→glm-5.3-flash`、`gpt-6.1-sol→gpt-6-astra`、`mimo-v2.5→claude-sonnet-4.6`。

- 其中 5 个是**同一家族/相邻版本**（差一档数字或同族变体），只有 1 个跨族。
- 默认（冻结）口径下唯一的错例也是同族近邻（`glm-5.3-flashx→glm-5.3-flash`）。

结论：大方向（家族）判得很准，**残余误差集中在"同族近邻区分"**。所以杠杆是"更强的判别头 + 更多该模型的参考样本"，而不是"再加一个打分组件"。

## 3. 优化路线

### P0 —— 先有可信的尺子（0 字节，前置，必做）

现在**从来没有对 APK 里那个编译后的定点制品跑过评估**（上表全部基于浮点制品）。所以第一件事是把评估对准真制品：

1. 把评估脚本从临时目录搬进仓库（`tools/fingerprint-eval/`），直接读 `assets/lm-fingerprint/lite-bank.bin`，跑同一套留出协议。定点量化（int32、SCALE 1e-6）如果有折损，那是**零成本的准确率修复**（提高 SCALE 或改 int16 定标即可）。
2. 报告改为**逐回答为主口径**（491 个样本，够用），逐模型与 top-3 作参考，并固定输出 bootstrap 噪声带。
3. 拟合 LDA 前先做正则化/降秩（见 P1），并把 `frac|eig|<1e-6` 这类病态度量打进报告，防止再次在病态解上读噪声。

产出：`tools/fingerprint-eval/` + 一份 baseline 报告（含真制品读数）。**没有这一步，后面所有改进都无法证明。**

### P1 —— 零字节的算法侧（预期最实在的收益）

| 项 | 做什么 | 字节 | 验证 |
|---|---|---|---|
| **① 判别头重训/正则化** | 把冻结的 LDA（53×429 权重、91 KB）换成在拟合半区上训练的**正则化线性头**（收缩 LDA / ridge / L2 逻辑回归；输入先白化，按 challenge 分组做 3 折 CV 选正则强度） | 权重 ≤91 KB（int8 23 KB），**随参考库下发，APK 零增长** | 无泄漏协议逐回答准确率 + 噪声带；必须同时看逐模型 |
| **② 组件融合改学习式** | 现在是固定 `0.5/0.5`。改成在拟合半区上对 `z(LDA)`、`z(质心)`（以及可选家族层得分）做一个小逻辑回归/线性 stack | 0（几个浮点参数进库） | 同上；同时报告固定权重的对照行 |
| **③ 置信度重新校准** | 现在 `softmax(z(合并分), betas[n-1])` 的 `betas` 是在冻结库上拟合的，实际会**过度自信**。用无泄漏的留出回答重新拟合 beta（3 个浮点数） | 0 | 用可靠性曲线/期望校准误差而不是准确率 |
| **④ 回答数与聚合** | 无泄漏分块读数 78.8%(n=1) → 85.1%(n=2) → **89.4%(n=3)**，n=1→3 涨 10.6 点、之后趋平；面板可以引导用户至少贴 3 条。同时试 `median` 替换 `mean` 聚合（单行改动）与"仅在 top1/top2 差距小时再问一轮"的选择性预测 | 0（只需 UI/文案改动） | 逐回答 + 覆盖率-准确率曲线 |

优先级：① > ③ > ④ > ②。① 是唯一直接提升判别能力的一项；③ 修的是"显示出来的概率是否可信"，对用户体验影响很大但不动 top-1。

### P2 —— 库外判定（+≈0.4 MB，修掉最危险的错误类型）

今天的失败不是"判错近邻"，而是**任何不在库里的模型都会被自信地叫成库内最近的一个**，且看起来很有把握。上游的 verifier 里有现成机制（`new_joint` 与校准块）就是干这个的。

- 做法：只取 verifier 的**拒绝判定路径**（高斯候选 + `new_joint` + 标定），不指望它提升排序（实测只多修对 1 个模型，且在噪声内）；输出一个"库外/不可判定"的状态。
- 体积：int8 + APK 内 deflate 后 ≈ **0.41 MB**（`verifier.references` 386 KB + `candidates` 20 KB + 其它小张量）；全套 float32 则是 +2.0 MB。**所以必须量化。**
- 先决条件（诚实说明）：本地**没有"库外模型"的回答样本**，所以目前的假接受率是无法测量的。要落地必须手工采集一小批（几个不在库内的模型 × 3 条回答，例如用别的渠道拿非库模型的回答），才能定阈值并给出假接受率。在此之前不要把"库外判定"写进发布说明。

### P3 —— 只有在 P1 未达标时才考虑

- **上游被忽略的逐环境数据**（`models[].counts` / `frequency_references`，53×36×355，f32 约 0.7–2.7 MB）：它比质心保留了更多分布信息，可能值得做成第三组件。但这是同一个信息的更细粒度版本，先验不如"正则化判别头"，且成本高。做法是**先零成本的筛查实验**（把头部输入换成这些原始分布，比较无泄漏准确率），只有明显赢才打包。
- **上游参考库更新**：上游若发布更新的参考数据（本地副本是 2026-09-29/30 口径），走已有的指纹库更新通道重发即可，但**必须先过 P0 的无泄漏评估**，否则"更新了"只是换了一批数字。
- **增加参考样本**：现在每模型只有 ~36 条（1,948/53，47 道题）。这是最确定的准确率来源，但需要拿 53 个模型跑固定题面，本地不具备条件——属于"上游数据问题"，不是我们能做的工程项。

## 4. 体积账（决定"稍微大一点"到底多大）

| 项 | f32 载荷 | int8 载荷 | APK 内 deflate 后（实测比值） |
|---|---|---|---|
| 现在随包下发的 `lite-bank.bin` | 396 KB | — | **313 KB**（399,470 → 313,426，0.785） |
| kNN 参考（不做） | 3.34 MB | 0.85 MB | +≈0.54 MB |
| verifier 全套（P2） | 2.48 MB | 0.55 MB | +≈0.41 MB |
| 重训判别头（P1①） | ≤91 KB | ≤23 KB | **0**（进参考库，不走 APK） |

- 记录里的"17.4 MB / 12.8 MB"是 JSON **文本**体积，是真实数值载荷的 **5.19 倍**，不要用那两个数字估体积。
- 推荐组合（P1 + P2）= 参考库从 313 KB 涨到约 **730 KB**，即 APK 增加约 0.4 MB；"稍微大一点没事"完全覆盖。
- 若哪天要下发 float32 全套（6.2 MB 载荷），会**超过当前 4 MB 的安装上限**（`MAX_INSTALLED_BYTES`），需要一并提高上限并走 `minAppVersionCode` 门槛。

## 5. 明确不做

1. **恢复 kNN**：3.34 MB（int8 +0.54 MB），实测零贡献（见 §1.2）。
2. **为了"更像上游"而照搬全部组件**：上游的完整公式在无泄漏逐回答上（75.8%）并不比我们现在的（78.6%）好；照搬的净效果是变大、不动准确率。
3. **用逐模型指标调参**：53 个决策的噪声是 ±8 点，调不出东西。
4. **引用泄漏口径的数字做宣传**：98.1% 是留出回答漏进 LDA 投影得到的，不能对外讲。

---

## 6. 无法在本地测量的三件事（诚实边界）

1. **verifier 的真实增益**：它的权重是在全部参考上拟合的（同样泄漏），且上游没有公开训练代码；要得到无泄漏的 verifier，只能自建训练流程，成本远超收益。
2. **库外模型的假接受率**：本地不存在"非库内模型"的回答样本，P2 的阈值在此之前都是拍脑袋。
3. **与上游 0.8919 的严格比较**：双方切分分组不同（我们没有他们的 CV 分组），所以只能各报各的、看是否落在噪声带内。
