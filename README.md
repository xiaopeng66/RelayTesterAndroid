# Relay Tester Android

Relay Tester 是一款 Android 原生的多供应商模型测试与余额查询工具，面向经常使用中转站 / API 代理服务的用户。它不依赖外部服务器，直接从手机向用户配置的 API 站点发起请求，支持模型可用性验证、批量测试、余额查询、模型指纹检测与配置迁移。

- 当前版本：1.5.0
- 下载地址：[GitHub Release v1.5.0](https://github.com/xiaopeng66/RelayTesterAndroid/releases/tag/v1.5.0)
- APK 大小：约 2.79 MB（模型指纹检测包按需下载，不占安装包体积）
- 支持系统：Android 8.0 及以上

## 核心功能

### 1. 多供应商管理

- 支持添加多个供应商，独立维护供应商名称、Base URL、协议、API Key、模型列表和测试参数。
- API Key 与余额查询令牌分别保存，均可加密存放在 Android Keystore。
- 支持同一站点切换不同模型配置，不必重复搭建。
- 全部配置可导入导出，便于备份和迁移。

### 2. 模型测试

- 支持 OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages 三种常用协议。
- 支持 `GET /models` 模型列表拉取，可自动识别站点的模型目录。
- 模型测试页支持“批量拉取模型”，并行刷新所有已配置供应商的模型列表；失败时会逐个列出供应商名称与原因。
- 支持为供应商开启“禁止测试”，开启后只刷新模型列表，不发送连通性测试请求。
- 批量测试时可配置并发数、超时时间、请求间隔、分批数量、批间暂停、失败重试与取消。
- 实时显示每个模型的成功 / 失败状态、延迟、完成原因、Token 用量和错误类型。
- 结果行分两行：第 1 行是状态点 · 模型名 · **有效 n/n**（跟在名字右边、同一行；三条全有效时用主色、不满 3 条用错误色）· 状态胶囊；第 2 行是指标胶囊与动作轨。动作轨固定三格（**指纹 · 复制 · 详情/收起**，指纹在复制左边，只有测试成功的行才有指纹），每格宽度恒定，所以成功行与失败行的图标始终在同一条竖线上，不会因为某一行多一个图标而左右跳。
- 支持按名称 / 状态 / 延迟 / 错误类型筛选，支持多关键词搜索、结果排序、复制与结果导出。
- 支持失败原因分类，如认证失败、余额不足、无权限、模型不存在、限流、超时、网络错误、响应格式异常和上游错误。

### 3. 高级测试

- 支持在一个测试任务中同时选择多个供应商的模型。
- 支持跨供应商关键词检索：输入模型名称关键词后，自动拉取当前所有供应商的模型目录，并列出匹配结果与来源。
- 支持从检索列表中手动勾选，一键添加到测试任务；编辑已有模型时，已添加来源会保持选中并锁定，移除后自动释放。
- 支持对同一模型配置多个来源，并单独并行测试某个来源；测试中保留旧结果并显示进行中状态。
- 支持对已有来源进行编辑、删除、重命名和单条测试。
- 模型卡片支持一键核对来源：站点已下架的模型会标注“已不存在”，并禁止再对其发起测试。

### 4. 余额查询

- 支持为不同供应商配置独立的余额查询模板。
- 内置 `new-api` 模板，可基于访问令牌查询可用余额、已用额度与套餐信息。
- 支持自定义余额模板，可配置请求方法、请求头、请求体、JSON 路径与换算方式。
- 支持批量并行查询多个供应商的余额，结果自动汇总。
- 余额结果以卡片形式展示，包含供应商、可用余额、套餐、刷新时间与换算后的数值。
- 支持双栏布局，减少超长供应商列表的滚动成本。

### 5. 模型指纹检测

- 让目标模型凭第一反应写出约 300 个 1–355 的整数，把结果与参考库比对，判断实际响应的是哪个模型。适合核对中转站是否暗中替换了模型。
- 参考库覆盖 53 个模型、12 个家族。**它不打进安装包**：进入面板时静默查一次更新清单，点「下载检测包」即下载并校验（大小 + SHA-256）后安装，之后评分**完全离线，不上传回答**。「查看支持的模型」会打开按家族分组的弹窗，名单来自当前包头。
- 检测包可在应用内更新或删除；静默检查不占用检测、手动检查和下载按钮，手动操作会接管在飞的后台检查。同一次检查未结束时重新进入面板不会重复发请求。除打开面板或主动操作外，没有后台轮询。删除会同时清掉主包与回滚副本，失败时如实保留可用状态。更新机制见 [检测包说明](docs/FINGERPRINT_DETECTION_PACKAGE.md)。
- 打分口径与上游 `shared-detector-v1` 一致（LDA 排序 + kNN 参考距离 + 质心基线，另有核验器给出检验分数并标注"排名与核验是否一致"），对拍证据见 `docs/FINGERPRINT_DETECTION_PACKAGE.md`。
- 支持两种模式：**API 直连**（选供应商与模型名，一键发送三道探测题并自动分析）与**手动粘贴**（没有 API Key 时，复制题目发到任意聊天界面，再把回答粘回来即可）。
- API 直连的模型名输入框是**筛选框**，右侧列表按钮打开模型选择弹窗，并显示勾选数量角标；目录外的名字可直接输入后勾选。多模型按**勾选顺序逐个检测**，题目区按模型分块：**每个模型一块、一块三栏**，块头是「序号 · 模型名 · 状态」（等待检测 / 正在检测 / 已出结果 / 失败），同一块的三栏等宽等高、横向对齐，所以整轮跑到第几个模型、哪一题在收、哪一题没过一眼就能看见（未开跑时先给一组没有块头的三栏，题目照旧可以先复制走）；进度条按**整轮题数**计（模型数 × 3，不随换模型清零）；每行结果的**展开面板就是全部内容**——评价卡（候选、家族、置信度、有效回答数、排名与核验是否一致）在上，候选榜在下，多模型与单模型一致，候选榜行内的供应商名用第三色（tertiary）标出。
- 每题显示接收状态与有效整数数；流式接收时实时显示「已收到 N 个整数」（窄栏里是紧凑写法「接收中 N」），结算后以校验通过的有效数字为准。检测过程中每格自带的复制按钮始终可用，随时可抄当前题目。**失败的格子自己带「重试」，点哪格补发哪格**：某一题一旦有结论（该模型已结算而它没答出有效回答）这一格的重试入口就出现，不必等整批跑完；并行发送三题打开时点下去立刻并发发出，逐题发送时它会**排在当前正在接收的那一题之后**——格子上先显示「排队中」，当前那一题一发完就插进去，然后整轮继续下一题（所以很慢的重试会把下一题顶后一点，这是「一次只发一条」的必然代价，超时上限仍是普通题目的 240 秒）。补发沿用原题，结果与整批结果按题合并，已收到的有效回答不会被回填盖掉。取消保留已完成答案。慢速站点可用开关改为逐题发送，点说明文字不切换开关。
- **检测历史**：每个模型测完留一条最近结论（时间、供应商、模型、候选、置信度、有效回答数、失败原因），面板顶部卡片可查看，最多保存 50 条、超出自动删最旧的，弹窗里可一键清空。记录只存本机应用私有目录，不导出、不上传。
- 中转站不支持流式回答时检测照常可用：对「不认识流式参数」的 400/415/422 自动回退整段请求，200 但非 SSE 的按整段解析（只是没有实时计数）。
- 测试模式与供应商的选中态为蓝色实心 chip；供应商较多时该行可横向滑动。
- 在“模型测试”的结果卡片上，测试成功的模型会多出一个指纹图标，点击即带着供应商与模型名跳转到指纹面板。
- 检测结果是**参考库内的封闭集合排序，不是身份证明**：不在库中的模型同样会得到最接近的候选，同家族相邻版本尤其难以区分。只有 3 条回答都有效时才给出置信度，1–2 条只给候选排序。
- 准确率的诚实口径：无泄漏协议下逐模型 88.7% / 逐回答 78.6%（评估见 `docs/FINGERPRINT_ACCURACY_OPTIMIZATION_SPEC.md`），同族相邻版本是主要错误来源。

### 6. 配置备份与迁移

- 支持一次性导出全部供应商、模型、测试参数、余额模板、API Key、PAT 和用户 ID，并保留当前选中的供应商。
- 支持加密备份与明文备份，可根据需要选择是否加密。
- 导入时可自动识别备份格式，先预览摘要，再确认覆盖，降低误操作风险。
- 导入完成不会自动请求任何站点，避免恢复配置时意外消耗请求额度或余额。

### 7. 用户体验

- 原生 Jetpack Compose 界面，支持浅色 / 深色 Material 3 主题。
- 供应商卡片、余额卡片和结果列表均针对手机竖屏优化，常用按钮保持足够大的触控区域。
- 支持双栏布局、抽屉、弹窗和快速筛选，方便小屏幕下高效操作。
- 支持快速双击卡片刷新，常用操作无需进入深层菜单。
- 启动页与品牌图标采用同一套视觉语言，减少应用内的多余过渡页。

## 安全与隐私

- 应用默认使用 HTTPS 请求；仅当 Base URL 显式填写 `http://` 时按明文请求，并会给出风险提示。
- API Key、余额查询 PAT 等敏感信息不写入测试结果和历史记录。
- 配置备份可加密存储，采用 PBKDF2 + AES-256-GCM。
- 导出测试结果 JSON 时默认不含 API Key、PAT 或用户 ID。
- **重定向只在同源内跟随**：仅当目标与供应商 Base URL 的协议、主机、端口完全一致时才继续，且从不接受 HTTPS 降级为 HTTP；跨域或降级重定向会被直接拒绝并给出提示。因此 API Key / PAT 不会被 3xx 带到第三方主机。OkHttp 自带的自动重定向与 SSL 重定向跟随已关闭，由应用自己逐跳跟随，超时对每一跳都生效。
- **导入余额模板只做静态语法校验，绝不执行脚本**：校验阶段不创建 JS 运行时，只扫描源码，因此导入他人分享或从站点拉取的模板时不会运行其中代码。校验会拦掉 `eval`、`Function` 构造器、`globalThis`、`WebAssembly`、`importScripts`、`debugger` 等逃逸入口，同时保留以 `function (json) {}` 形式书写的 `extractor`。
- 余额查询脚本在受限 JS 环境（QuickJS）中运行，无法访问 Android、Java 或网络底层 API。诚实说明其边界：QuickJS 的 Android 绑定**没有提供执行中断接口**，所以脚本仅在**用户主动点击查询**时才运行，且始终不在主线程（界面不会卡死）；本应用无法为它设置"到点强杀"的硬时限——能限制的是"什么时候跑"和"跑在哪"，不是"跑多久"。请只使用自己信任的模板。
- 供应商配置默认只保存本地，不会上传到任何第三方服务器。

### 已知限制（如实登记，本轮安全复审中评估后决定不修的项）

- **屏幕内容未加 FLAG_SECURE**：应用不设置 `FLAG_SECURE`，因此多任务切换器的预览截图与录屏会包含供应商名称、密钥输入框等界面内容。设置它会让用户自己也无法截图分享界面，权衡后不加。
- **模板可以把密钥写进 URL**：余额模板的端点模板由用户填写，若把 `{{apiKey}}`/`{{accessToken}}` 放进 URL 查询串（部分站点确实这样设计），密钥就会出现在请求 URL 里，可能被上游日志记录。应用不阻止这种写法，因为有些站点只支持这种方式；请尽量把凭据放在请求头。
- **配置导出不是原子写**：导出配置走系统文件选择器（SAF），直接写入用户选定的目标文档。SAF 不支持"写临时文件再换名"，所以写入中途失败（拔线、磁盘满）会在目标位置留下半个文件。失败时应用会报错，但不会替你清理那个残件。
- **失败重试会重放非幂等的 POST**：模型测试失败自动重试时重发的是同一个对话请求。若上一次请求其实已被上游处理、只是响应丢失，重试会再计一次费用（重复计费通常只有 1 次请求的量）。这是重试机制的固有代价。
- **错误脱敏依赖可识别形状**：上游错误中的凭据字段、Bearer、`API key provided` 等话术以及常见 `sk-` / GitHub token 会替换为 `***`，兼容引号和 JSON 字段；普通错误话术保留。它不会按本次提交的密钥逐值比对，任意无前缀裸值仍可能漏网。不要把报错原文贴给不可信的第三方。

## 使用方式

1. 安装 APK 后打开应用，进入“模型测试”页面。
2. 点击“添加供应商”，填写供应商名称、Base URL、协议与 API Key。
3. 点击“获取模型”拉取模型列表，或者在“高级测试”中手动选择模型。
4. 按需调整测试参数，例如超时、并发、Prompt、过滤词、重试和分批数量。
5. 开始测试后，可实时查看每个模型的响应结果和错误信息。
6. 切换到“余额查询”页面，配置模板与访问令牌，即可查询余额。
7. 切换到“指纹检测”页面，选好供应商，在筛选框中输入关键词找到模型并勾选（可多选，按勾选顺序逐个检测），然后点击“开始检测”；或改用“手动粘贴”模式把三道题目的回答粘回来分析。
8. 通过右上角“导入或导出配置”功能，可迁移全部配置到其他设备。

## 构建开发

使用 Android Studio 打开本目录，选择 JDK 17，并执行：

    .\gradlew.bat assembleDebug

若 Windows 上的 Oracle JDK 17 在构建启动阶段报 `Unable to establish loopback connection`，可使用项目内的 TCP 回环兼容包装脚本：

    .\tools\build-android.ps1 assembleDebug

调试包位于 `app/build/outputs/apk/debug/app-debug.apk`，优化包位于 `app/build/outputs/apk/optimized/app-optimized.apk`。
